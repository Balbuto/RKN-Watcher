# Безопасность и ограничения

## Исправления безопасности в v3.2.1

- **IPv6 для allow/deny-списков**: адреса разделяются по семействам, IPv6 уходит
  в `family inet6`-наборы и в отдельную цепочку `RKN_GEOIP_HOOK6`. Раньше IPv6-запись
  просто отклонялась, и на dual-stack сервере allow-список фактически не защищал —
  трафик по IPv6 обходил правила;
- **явный netfilter-бэкенд** (`NETFILTER_BACKEND`): исключает ситуацию, когда правила
  пишутся в `iptables-nft`, а проверяются через `iptables-legacy` (и наоборот).
  Расхождение видно в `doctor` и настраивается;
- **ротация снапшотов по возрасту**: старые снапшоты удаляются (по умолчанию >30 дней),
  каталог не растёт бесконечно; последние `SNAPSHOT_KEEP` сохраняются всегда;
- **детерминированный разбор `settings.conf`**: при дублировании ключа действует
  последнее значение, `doctor` показывает список дублей — это исключает ситуацию
  «правило безопасности прописано ниже, но не работает»;
- **некорректный адрес** в allow/deny-списке — ошибка конфигурации (fail-closed),
  а не тихий пропуск записи.

## Исправления безопасности в v3.2

- **fail-closed вместо fail-open**: некорректное boolean-значение в `settings.conf` —
  ошибка применения, а не молчаливое отключение блокировки;
- **защита от самоблока**: `RKN_GEOIP_HOOK` возвращает трафик для `lo` и
  `ESTABLISHED,RELATED`; при включении GeoIP скрипт предлагает добавить текущий
  SSH-IP в allow-список (`rkn-watcher allow-my-ip`);
- **снапшоты перед каждым apply** (`/var/lib/rkn-watcher/snapshots/`) и команда
  `rollback` — аварийное восстановление доступа из консоли одной командой;
- **атомарное применение правил** одним `iptables-restore`: нет окна с
  полуприменённым набором правил и гонок с `xtables lock` (`-w` во всех вызовах);
- **sanity-гейт списков**: компрометация или сбой апстрима, «схлопнувший» список,
  не приводит к отключению блокировки или массовому `DROP`;
- **systemd hardening**: `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`,
  `PrivateTmp`, `CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_RAW`;
- **права на конфигурацию**: `settings.conf`, `whitelist.json`, `blacklist.json` —
  `0600 root`; бэкапы — `0600`; ротация логов — `0640 root:root`;
- **логи с ротацией** (`/etc/logrotate.d/rkn-watcher`), `truncate` вместо `: >`
  при очистке.

## Исправления безопасности в v3.1

- пользовательский ввод не встраивается напрямую в inline Python-код;
- JSON-конфигурация записывается атомарно через временный файл и `os.replace()`;
- один advisory file lock покрывает весь цикл чтения, изменения и записи
  конфигурации — параллельные вызовы редактора не теряют изменения;
- legacy-значения boolean разбираются явно: `"false"` не считается истинной
  непустой строкой и не включает GeoIP;
- параллельные `update` и `apply` сериализуются через `flock`;
- обновление `ipset` выполняется атомарно через временный set и `swap`;
- checksum manifest пересобирается скриптом релиза и проверяется шагом
  `sha256sum -c` в GitHub Actions.

## Известные ограничения

- **источники списков не подписаны.** TSPU/GOVIPS скачиваются по HTTPS из чужих
  репозиториев (`tread-lightly/CyberOK_Skipa_ips`, `C24Be/AS_Network_List`), подписей
  они не публикуют; компрометация апстрима остаётся риском. Частично смягчается
  sanity-гейтом (список, «схлопнувшийся» вдвое или выросший в 5 раз, не применяется);
- **при отсутствии `ip6tables`** IPv6-трафик не фильтруется — `doctor` предупреждает
  об этом явно (`ip6tables: нет (IPv6 не защищён)`);
- **country GeoIP — это CIDR-фильтрация**, а не MaxMind-база: привязка идёт по
  опубликованным country-block спискам ipdeny;
- **`PORT_POLICY=geoip_only` (по умолчанию)** фильтрует только порты из
  `FILTER_PORTS`; сценарии «фильтровать всё» требуют осознанного
  `PORT_POLICY=strict`;
- **не рекомендуется** запуск на хосте, где `iptables` полностью перезаписывается
  внешней системой (оркестратор, firewall-менеджер панели, CM-система). Docker
  безопасен: hook остаётся в `INPUT`, правила docker живут в `FORWARD`/`NAT`,
  но `doctor` про него предупреждает.

## Что важно в эксплуатации

### Скрипты работают от root

Это необходимо для управления `iptables`, `ipset` и `systemd`. Перед включением GeoIP
на удалённо администрируемом сервере внимательно проверьте правила стран, allow и deny
и заранее выполните `sudo rkn-watcher allow-my-ip`.

### GeoIP по странам зависит от внешнего источника CIDR

Используется `ipdeny.com`. Если источник недоступен:

- будет использован локальный кэш (`/var/lib/rkn-watcher/cache/countries/`), если он есть;
- если кэша нет, обновление country-set не выполнится (старый набор продолжит работать).
